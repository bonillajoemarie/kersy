# Kersy Phase 1.5 — Cockpit shell + visual redesign

**Owner feedback (2026-08-15, after seeing Phase 1):** all four design axes disliked (bare/unpolished, layout, crude graph, flat colors); "font feels generic — make it smoother"; expected a **prompt input** and a **project explorer with files**. Owner approved pulling both forward ("Yes, minimal prompt bar"; explorer confirmed) and directed using **our experts** (the cs-ai-platform agent definitions) for implementation.

## Layout (one window, cockpit)

```
┌──────────────────────── top bar (filters · discovery · legend) ───────────────┐
│ EXPLORER      │                                              │ TASKS          │
│ project tree  │              agent map (GPU)                 │ status cards   │
│  ▸ kersy      │   glow nodes · label pills · hover tips      │                │
│  ▾ workspace  │                                              │                │
│    ▸ files…   │                                              │                │
│    ◦ sessions │──────────────────────────────────────────────┤                │
│               │  drill-in (slides over map right edge)       │                │
├───────────────┴──────────────────────────────────────────────┴────────────────┤
│ ⌨ prompt bar: [project ▾] [ask Claude anything…            ] [Run]            │
├────────────────────────────── status bar (rss · watcher) ─────────────────────┤
```

- **Left — Project Explorer:** discovered projects (slug → real path), each expandable: `files/` (lazy directory tree, read-only, dirs-first sorted, dotfiles dimmed, `node_modules`/`target`/`.git` collapsed-by-default and marked) and `sessions/` (that project's sessions, status-dotted; click focuses+zooms the map to it). Empty state teaches: "Projects Claude Code has worked in appear here."
- **Bottom — Prompt bar (thin Phase-4 slice):** project picker + single-line input + Run. Runs the REAL `claude` CLI headless (`claude -p "<prompt>"`, cwd = chosen project, detached; stdout to a log file under the app's data dir). The new session appears on the map via the existing watcher — no bespoke chat UI in this phase. If the CLI is not found, the bar is disabled with an explanatory tooltip ("Claude Code CLI not found on PATH"). No shell string interpolation — args passed as an array (Command::arg), cwd validated against discovered project paths.
- Task pane and drill-in stay right/overlay, redesigned (below). Map stays center.

## Visual redesign

**Design north star (owner, 2026-08-15): Zed editor** — its fonts, smooth navigation, and cleanliness. Concretely binding:
- **Typography:** Zed's typefaces are IBM Plex derivatives, so bundle **IBM Plex Sans** (UI) and **IBM Plex Mono** (code/paths/commands) as woff2 assets in `ui/src/assets/fonts/` (OFL licenses committed alongside; CSP-safe local assets). `-webkit-font-smoothing: antialiased; text-rendering: optimizeLegibility;` ~~UI at 13px base, scale 11/12/13/15/18~~ **AMENDED (owner, 2026-08-15: "make the font 50% larger")**: base 20px, scale 16/18/20/23/27 (the original scale ×1.5, rounded); overlay/canvas label px sizes scale by the same factor (map labels 11px → 16px, tooltip text likewise). `tabular-nums` for numeric data. Panel widths may need +~25% (explorer ~300px, tasks ~380px) so the larger type breathes — implementer judgment within the grid.
- **Cleanliness:** flat surfaces separated by **1px hairline borders only — no drop shadows**; 4–6px radii; generous-but-tight spacing on a 4px grid; minimal iconography (inline SVG, 14px, stroke style); chrome text low-contrast until hovered; one accent, used sparingly (focus rings, primary button).
- **Smooth navigation:** every transition 120–180ms `cubic-bezier(0.2, 0, 0, 1)` (Zed-fast, never bouncy); panel expand/collapse animates height; explorer tree rows highlight instantly on hover (no transition on hover-in, transition on hover-out); camera focus-on-session glides (lerp); drill-in slides in. All animations terminate (0%-idle rule).

**Color system (dataviz-skill validated, 2026-08-15):**
- Surfaces stay Darcula: bg `#2B2B2B`, panel `#3C3F41`, border `#323232`, plus a new elevated step `#45494A` (hover/cards) and inset step `#242424` (wells, prompt input).
- **Node state colors re-stepped and machine-validated** on `#2B2B2B` (all five checks pass, worst ΔE 26.8 CVD / 31.8 normal): `active #d95926`, `idle #3987e5`. `stale #8a8a86` is deliberately drained (status semantics). Old `#CC7832` remains as the *brand accent* (buttons, focus rings, selection), no longer a data color.
- `success #0ca30c` / `error #d03b3b` (validated status hexes) appear **only paired with an icon + label** (✓ receipts, ⚠ badges) — never color-alone. This is the dataviz status rule and it is binding.
- **Legend chip row** in the top bar: ● active · ● idle · ● stale, each a dot + word — the map is a visualization with ≥2 series, so a legend is mandatory.

**Graph rendering upgrade (owner: "crude"):**
- Nodes: soft radial **glow halo** behind active nodes (pre-rendered gradient sprite on the overlay canvas, tinted per state), 1.5px darker rim on all discs, session nodes get a subtle inner dot when they have subagents.
- Pulse stays but eases (sin² curve), and spawn animation eases in over ~300 ms (scale 0→1).
- Labels become **pills**: rounded dark chip (`#242424` @ 85% alpha) behind text, 11px Inter, max 40 chars, hidden below zoom 0.5 except for active nodes.
- Edges: 1.5px, `#4a4d4e` at 70% alpha; parent→child gets a subtle arrowless taper (thicker at parent). Straight lines stay (cheap, readable).
- **Hover layer (dataviz rule — interactive by default):** pointermove hit-test shows a tooltip chip (agent type · status word · current activity · context k) near the cursor; hit target ≥ node radius + 6px.
- Zoom/pan smoothing: camera lerps toward target (~0.2/frame) — but the lerp must not keep the rAF loop alive once |delta| < 0.1px (0%-idle rule still binds).

**Human names everywhere (owner, 2026-08-15: "I don't understand numbers"):** raw UUIDs, agent hashes, and bare task numbers must never be the visible label anywhere in the UI. Display precedence:
- **Session:** its AI title (`aiTitle`, already parsed) → else its live `currentActivity` → else "Session in <project folder name>" — never the UUID.
- **Subagent:** its `description` ("Verify customer_ref validation") → else `agentType` — never the hash.
- **Task:** its `subject` — already human; the numeric id appears nowhere.
- **Project:** the folder name (last path segment), full path in the tooltip.
- IDs live only in tooltips (small, secondary ink) for debugging. The map labels, explorer rows, task cards, drill-in header, and prompt-bar picker all follow this rule. Missing-title stub sessions show their relative age instead ("stale · 12 days").

**Panels:**
- Panel headers: 12px uppercase tracking-wide secondary text with a hairline underline.
- Tasks become **cards**: subject (Inter 13), status chip (colored dot + word), blocked-by row with ⛔ + names, session link. Groups keep counts; completed collapsed.
- Drill-in: sectioned (Identity / Context gauge / Receipts / Files / Feed), gauge gets tick marks at 60/85%, receipts rows get ✓ (success) / ✗ (error exit) icons, feed rows monospace with dim timestamps.
- Buttons/inputs: consistent 28px height, `#45494A` fill, 1px border, `#CC7832` focus ring, 4px radius. Checkboxes become toggle pills (Live only · Pause layout).

## New backend surface (minimal)

- `list_dir(path) -> Vec<{name, is_dir}>`: only serves paths **under a discovered project's real path** (canonicalize + prefix check; reject otherwise) — the explorer's lazy tree. Sorted dirs-first, then files, case-insensitive.
- `run_prompt(project_path, prompt) -> Result<(), String>`: validates project_path against discovered projects, spawns detached `claude` with `["-p", prompt]` via Command::arg (no shell), cwd set, stdout/stderr → `<app-data>/prompt-logs/<timestamp>.log`. Returns error string if spawn fails.
- `cli_available() -> bool`: `which claude` once at startup, cached.
- Project real paths come from `project_dir_to_path(slug)` — best-effort; explorer marks a project "path not found" (with the tried path) when the dir doesn't exist rather than hiding it.

## Constraints carried forward (all still bind)

Budgets (≤15 MB rpm, 0% idle CPU, memory rules), CSP unchanged (fonts are local assets), deps: **no new JS runtime deps** (fonts are assets, not packages); Rust may add nothing (std Command suffices). Tests: store/sim suites stay green; new Rust commands get unit tests (path-guard rejection cases are mandatory); legend/status never color-alone.

## Out of scope

File *editing* (Phase 2's CodeMirror), chat conversation UI, multi-model (Phase 4), streaming prompt output into a pane (the map + drill-in IS the output view for now).

## Expert usage (owner directive)

Implementation dispatched to general-purpose subagents **bound to the adapted expert definitions** in `.claude/agents/` (frontend-ui-ux for UI tasks, qa-engineer for the verification pass) — adapted from cs-ai-platform's experts for Kersy's stack (plain TS + canvas, no Vue). The perpetual-new-hire rule from that expert binds every empty state, disabled control, and label in this spec.
